# [[378,18,27]] lifted product over F_2[M_27 x Z_7] at check weight 8, reproducing the paper's published distance bound

## Direction & hypothesis

Target cell: weight-8 x unrestricted (CSS), which is where the verifier places
a check weight of 8. The source is arXiv:2608.08996 Table 1, published at n =
378, k = 18, w = 10 on the estimator's upper bound of 27. Eight of that
paper's other codes are already board entries citing it, but this one was
missed: no entry shares (n, k) = (378, 18) and nothing dominates it at n <=
378, k >= 18, d >= 27, w <= 8, giving kd^2/n = 34.71.

## What was searched

No search for the construction: it reproduces from the paper's Supplementary
Information, which sits at the end of main.tex after the References and so is
invisible to a text search of the article body. G = M_27 x Z_7 with K = {e}
(free action) and 1x1/1x1 boundary maps, so the coset-orbit balanced product
reduces to the ordinary lifted product over G, i.e. the two-block
group-algebra form already in the kit. Every invariant reproduces: n = 378, k
= 18 by GF(2) rank, w = 8, H_X H_Z^T = 0 over GF(2), and d = 27 on both Pauli
sides. M_27 is built as metacyclic(9, 3, 4) -- C_9 rtimes C_3 with the C_3
action given by x -> x^4 -- times Z_7 on generator u, indexed (i, j, v) ->
(i*3 + j)*7 + v. A sibling entry from the same table, [[390,36,<=30]], was
also attempted and does NOT reproduce: its check matrices come out full rank
on both sides and k = 0, which is inconsistent with the published k = 36, so
it is recorded as a dead end rather than fitted to the target.

Two fresh rungs at 1,000,000 trials per side, each measuring X and Z
separately and both returning 27, agreeing with the paper's published bound.
The document's own search at 200,000 trials read X = 28 and Z = 27, so the
deeper ladder is what pins X at 27 rather than leaving it at the shallower 28.

## Dead ends

- [[390,36,<=30]] from the same table does not reproduce: the group (Z_39 x
  Z_5, order 195) and the element indexing check out, and n = 390, w = 10 and
  CSS commutation all hold, but both check matrices come out full rank and k =
  0. That is inconsistent with the published k = 36 for any construction, so
  either the Supplementary Information entry was misread or its 1x1/1x1
  free-action case carries a convention the [[390,32]] entry does not. Not
  fitted to the target k.
- The fast backend cannot always return a requested side:
  distance_rand_witness yields only the lighter of the two sides, so when one
  side is strictly lighter the other is unreachable at any seed. The staging
  helper therefore collects each side from whichever orientation yields it and
  falls back to numpy's one-sided lightest_logical, which is what the kit's
  own function implements.
