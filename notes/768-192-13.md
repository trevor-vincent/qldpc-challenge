# [[768,192,13]] pair-partition code over F_4[C_48] with a full regular canonical logical frame, from arXiv:2610.06820.

## Direction & hypothesis

Target cell: weight-8 x unrestricted (CSS), the cell the verifier assigns a
check weight of 8. The opening was numerical. arXiv:2610.06820 tabulates
twenty-four LP and PP codes whose distances it certifies exactly; screening
every (n, k, d, w) against codes/ left five absent and of those only this one
and [[512,128,20]] were undominated, and they are in different weight classes
(w = 8 here, w = 10 there), so they are two points rather than one. At kd2/n =
42.25 with n = 768 it sits at the blocklength rule's sparse end: admissible
because n <= 700 fails but n <= 1000 with w <= 8 and d <= 40 all hold.

## What was searched

No search. This is a reproduction of a published instance: the cyclic group
C_48, the field F_4, three seed rows with eight exponent/coefficient pairs
each, all fixed by the companion catalogue entry. The binary checks were
rebuilt with the source authors' own routine
(github.com/yeon-lee/public-regular-logical-frames, src/rlf.py ::
reconstruct), which applies the pair-cancellation constraint of Eq. (19) and
the reversing-symmetry placement of the correction pivots; a hand expansion
that omitted those gave n = 1024 and failed CSS commutation, so the authors'
routine is the construction rather than an implementation detail of it.
Verified here against the published values: n = 768, k = 192 by GF(2) rank,
maximum row weight 8 on both sides, and H_X H_Z^T = 0 over GF(2). The paper
reports this distance as exact.

## Dead ends

- Hand-expanded the quaternary checks into binary columns without the
  pair-cancellation constraint: produced n = 1024 instead of 768 and H_X H_Z^T
  != 0. The reversing-symmetry pivot placement is load-bearing, not cosmetic.
- Seven other codes from the same catalogue (lp-f4-476-56-14, lp-f4-544-64-15,
  pp-f4-256-64-12, lp-f4-544-64-14-w8 and the w=11 twins of the 512-length
  codes) were built and screened at their paper distances: each is either
  dominated on (n, k, d, w) by an existing entry or strictly dominated by the
  w=10 variant filed alongside this one.

## Reproduction

uv run python; catalogue = json.load(open('catalogue.json'))['constructions'];
code = next(x['code'] for x in catalogue if x['code']['id'] ==
'pp-f4-768-192-13-w8'); hx, hz, seeds = reconstruct(code). That returns the
binary (H_X, H_Z). The construction itself is the pair-partition of
arXiv:2610.06820 Sec. V: a reversing r-by-2M PP array over R = F_4[C_P] with P
= 48, check basis raw, correction pivots on disjoint sectors and shared free
coordinates, exponents and F_4 coefficients as tabulated in the entry.
